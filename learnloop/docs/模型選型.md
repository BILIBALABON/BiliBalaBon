# 模型選型

每個 agent 用哪個模型、思考多深（effort），寫在 `.claude/agents/<名稱>.md` 的 frontmatter。
這份文件說明怎麼選、為什麼這樣選，以及哪些有實測、哪些只是推估。

## 結論

| agent | 任務特性 | 模型 | effort | 備援模型 |
|---|---|---|---|---|
| ingest-document | 每檔一個、平行；讀擷取出的文字，照固定四段格式忠實整理 | Haiku 5.5 | high | Sonnet 5.5 |
| 　↳ 需要看圖的來源 | 掃描 PDF、板書與講義照片：逐頁看圖、辨識手寫、表格與公式 | Opus 5.5 | medium | Sonnet 5.5 |
| ingest-audio | 整理語音辨識逐字稿；靠領域知識還原同音錯字與專有名詞 | Sonnet 5.5 | medium | Opus 5.5 |
| ingest-video | 逐字稿＋最多 24 張關鍵畫面；讀投影片、板書、圖表並與口述對齊 | Opus 5.5 | medium | Sonnet 5.5 |
| planner | 讀完全部來源整理，排學習順序與章節；產出很小，後面每一站都依它工作 | Opus 5.5 | high | Sonnet 5.5 |
| organizer | 長篇筆記：融合多份來源、逐點標出處，輸出量大 | Sonnet 5.5 | medium | Opus 5.5 |
| fact-checker | 多輪搜尋、讀大量網頁，判定每個主張成不成立 | Sonnet 5.5 | high | Opus 5.5 |
| enricher | 搜尋補充資料與說明影片，挑選後改寫 | Sonnet 5.5 | medium | Opus 5.5 |
| integrator | 依查證結果修訂筆記、逐項交代處理方式 | Sonnet 5.5 | medium | Opus 5.5 |
| slide-composer | 最終簡報與 SVG 示意圖版面；輸出量在產出者中最大（僅次於審核者） | Sonnet 5.5 | high | Opus 5.5 |
| reviewer | 唯讀的最後判斷：在大量輸入裡找錯、評分 | Opus 5.5 | high | 不設 |

`python3 -m learnloop.agents --list` 會印出目前生效的選型。

## 價格（2026 年 10 月，每百萬 token，美元）

| 模型 | model ID | 輸入 | 輸出 | 快取讀取 |
|---|---|---|---|---|
| Haiku 5.5 | `claude-haiku-5-5` | 0.10（提示超過 10 萬 token 時 0.50） | 0.50（2.50） | 0.01 |
| Sonnet 5.5 | `claude-sonnet-5-5` | 2 | 10 | 0.20 |
| Opus 5.5 | `claude-opus-5-5` | 4 | 20 | 0.20 |
| Fable 5.1 | `claude-fable-5-1` | 10 | 50 | 0.25 |

Sonnet 5.5 與 Opus 5.5 的快取讀取同價。agent session 每一回合都會重讀前面的對話，那部分大多走快取，
所以兩者實際的價差比定價表的兩倍小，主要差在第一次讀進來的內容（例如圖片）與輸出。

## 選型原則

1. **比的是「完成一件工作」的成本，不是每個 token 的單價。** 一個階段做得不好，閘門或審核會把它退回來；
   多跑一輪（甚至多一輪「編排＋審核」）的錢，往往比一開始就用好一點的模型還多。
2. **預設用 Sonnet 5.5。** 多數 agent 的工作是「多步工具使用＋寫作」，這是它的主場，單價是 Opus 5.5 的一半。
3. **降到 Haiku 5.5 要三個條件都成立：**
   工作量隨檔案數放大（每檔一個 worker、平行跑）；任務是忠實擷取、照格式整理，不需要外部知識或深度判斷；
   後面還有人檢查（整理筆記、查證、審核都會回頭對照原始資料）。只有文字來源的 ingest-document 三者都符合。
4. **升到 Opus 5.5，符合其中一項即可：**
   - **產出小、但影響全局**（planner）：大綱決定後面每一站的結構，多花的錢很少，影響最大。
   - **判斷本身就是工作**（reviewer）：Opus 5.5 在大量輸入裡挑錯更細、誤報更少；少一次不必要的退回，就省下一輪編排＋審核。
   - **品質取決於讀圖**（ingest-video、掃描檔與照片）：Opus 5.5 讀圖表、示意圖與位置關係（箭頭連到哪個方塊）
     明顯比其他模型準，而且不需要額外的裁切、放大工具。
   - 反過來，**輸出量大的工作留在 Sonnet 5.5**：Opus 5.5 的輸出單價是兩倍。slide-composer 原本也想升級
     （最終成品、審核退回都回到這裡），但實測它的輸出量在產出者中最大（見下方「實測與估算」），升級讓整條流程貴約兩成；
     而它的版面由閘門機械檢查（條列上限、SVG 白名單與字級）、內容由 Opus 審核把關，所以改用 Sonnet 5.5 搭 high effort
     換取計算 SVG 座標與字寬的思考。編排者與審核者是不同模型，審核也更獨立。
5. **不用 Fable 5.1。** 單價是 Opus 5.5 的 2.5 倍、不開放給零資料保留（ZDR）的組織、單一回合時間長。
   這條流程每一站都有閘門與審核把關，最強模型的邊際效益抵不過價差。想試的話，最值得的位置是 reviewer。
6. **effort 一律明確寫。** 同名等級在不同模型的思考量不同，預設值也不同（Opus 5.5、Haiku 5.5 預設 medium；Sonnet 5.5 預設 high），
   不寫就會隨模型而變。
   - medium：多步工具使用與一般寫作的建議起點。
   - high：判斷密集（planner、fact-checker、reviewer）、需要空間計算（slide-composer 的 SVG 版面）；
     Haiku 5.5 的 ingest-document 也用 high，換取嚴格遵守四段格式，以它的單價幾乎不增加花費。
   - low：不用。低 effort 在長任務上較容易提早結束、略過自我檢查；閘門會擋，但會多耗一輪。
   - xhigh／max：沒有量測證據顯示品質提升前不用。
7. **備援模型（fallbackModel）。** 主要模型過載或無法使用時自動改用，無人值守時少開處置單。
   Haiku → Sonnet、Sonnet → Opus（品質不降）；Opus 產出者 → Sonnet（後面還有閘門與審核）。
   **審核者不設**：最後一道把關不應悄悄換成較弱的模型，寧可重試或開處置單。
8. **統一覆寫只用來測試。** `config.toml` 的 `models.override`（或環境變數 `LP_MODEL`）讓全部 agent 改用同一個模型，
   同時停用備援與看圖路線，避免測試時又被換回貴的模型；effort 照各 agent 的設定。

## 怎麼運作

- frontmatter 欄位：`model`、`effort`、`fallbackModel`，以及選用的 `visionModel`、`visionEffort`。model 一律寫完整 ID，
  不用 `sonnet` 這類會隨版本漂移的別名。
- orchestrator（`learnloop/pipeline.py`）每次啟動 session 前呼叫 `agents.choose_model()`：擷取階段讀 `raw/<代號>/meta.json`，
  來源標為 `needs_vision`（掃描檔、圖片、沒有音軌的影片）且 agent 有 `visionModel` 時改用它。
- `learnloop/runner.py` 把結果傳給 `ClaudeAgentOptions` 的 `model`、`effort`、`fallback_model`；
  `scripts/loop.sh` 用 `python3 -m learnloop.agents --choose` 取得同一份結果，傳給 `--model`、`--effort`、`--fallback-model`。
- 狀態檔記下每個階段與 worker 實際用的模型；監控介面的階段詳情、worker 表格與即時紀錄都會顯示。
- 自動測試（`TestModelSelection`）守住以下規則，改 agent 檔時若違反會失敗：
  每個 agent 都寫了完整 model ID 與合法的 effort；平行擷取是所有 agent 中最便宜的一級、要看圖時會升級；
  審核者不比任何產出者弱、effort 不低於任何產出者、不設備援；規劃者不比整理筆記的 agent 弱；
  選型確實傳到 SDK 與 CLI（以「故意改壞程式」確認過這些測試會失敗）。

## 版本需求

需要 `claude-agent-sdk` 0.2.165 以上（內建 Claude Code CLI 2.1.294）。實測 0.2.159 內建的 2.1.281 不認得 5.5 世代的模型：
仍能執行，但費用照錯的單價計算（Haiku 5.5 被高估約 35 倍），預算上限與介面上的花費跟著失準。
`python3 -m learnloop doctor` 會檢查版本。

## 實測與估算

### 真實執行（2026-10-14）

- 樣本：一頁熱傳導講義（文字），期望 6 張，上限 NT$100。為了省錢，所有 agent 統一用 Haiku 5.5（`LP_MODEL=claude-haiku-5-5`）。
  執行環境的網路政策擋掉所有外部網頁，所以連結檢查用「只警告」模式。
- 結果：前處理、擷取、大綱、筆記、查證、整合、編排都通過閘門。補充因為打不開任何網頁、不肯無中生有，三輪沒過，
  在處置單選「略過補充」；查證也因此把 11 個主張全判為「未能查證」。審核三輪都沒過（完整性、學習效果 3 分），
  處置單逾時，採用保守的預設選項「停止」。
- 實際花費 US$0.655（約 NT$21）。其中查證＋補充 US$0.43，大多是網路搜尋的附帶費用，與選哪個模型無關。

### 依實測 token 用量推估各種選型的花費

把這次每個 session 的 token 用量（從 Claude Code 的對話紀錄加總）套上各模型的單價。
前提是各模型用掉的 token 數相同；實際上不同模型、不同 effort 的思考量不同，只能當量級參考。
以 Haiku 單價重算的結果與 CLI 回報的實際花費，在不含搜尋的階段相差不到 5%（快取寫入以 1 小時快取的兩倍輸入單價計）。

| 階段 | 輸出 token | 快取讀取 token | 本選型（美元） | 原本：全部 Sonnet、審核 Opus |
|---|---:|---:|---:|---:|
| 擷取 | 4,306 | 32,392 | 0.004（Haiku） | 0.08 |
| 規劃大綱 | 3,651 | 44,686 | 0.16（Opus） | 0.09 |
| 整理筆記 | 5,718 | 77,345 | 0.13 | 0.13 |
| 查證 | 11,607 | 380,080 | 0.43 | 0.43 |
| 補充（三輪都失敗） | 8,389 | 799,510 | 0.44 | 0.44 |
| 整合修訂 | 9,637 | 98,004 | 0.21 | 0.21 |
| 編排簡報（含 2 次退回修改） | 56,581 | 272,019 | 1.04 | 1.04 |
| 審核（3 輪） | 73,753 | 182,711 | 2.46（Opus） | 2.46 |
| **合計** | | | **約 4.9** | **約 4.9** |

查證、補充、審核另含每次搜尋 US$0.01 的費用。同一份用量全部改用 Sonnet 5.5 約 US$3.7，全部用 Opus 5.5 約 US$6.8。

怎麼解讀：

1. **這麼小的樣本，本選型和原本差不多**：擷取省下的（Haiku）剛好抵掉規劃多花的（Opus）。擷取的花費與教材長度、
   檔案數成正比，教材越多，Haiku 省得越多；影片改用 Opus 則每支會多一些。
2. **一半以上的錢花在「審核 → 退回修改」的迴圈**：每多一輪約 US$0.8（審核）＋ 0.35（編排修改）。
   所以最省錢的是減少不必要的退回：審核者用判斷準、誤報少的模型，並清掉規則之間的衝突（見 `docs/可行性審查.md` 第六節）。
3. **slide-composer 改回 Sonnet 5.5 就是依這份數據**：它的輸出量僅次於審核者，升到 Opus 會讓總花費多約兩成，
   而它的版面已有閘門把關、內容已有 Opus 審核。
4. **還要再省，先調 reviewer 的 effort**（high → medium）：審核約佔一半花費，Opus 5.5 的 medium 已優於上一代 Opus 的 high。
   調整前請用同一份教材各跑一次，比較審核分數與審核輪數。

## 怎麼調整

- 改 `.claude/agents/<名稱>.md` 的 `model`／`effort`／`fallbackModel`，下次啟動 session 就生效，不必改程式。
- 要拿數字做決定：同一份短教材用兩種設定各跑一次，比較 `output/report.json` 的 `stages.*.cost_usd`、審核分數與審核輪數。
- 只想試流程、不在意品質：`config.toml` 的 `models.override = "claude-haiku-5-5"`。
